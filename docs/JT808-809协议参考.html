一、JT/T 808 消息清单 0x0001 ~ 0xE0xx

终端与监控平台间的通讯消息。消息头按版本自动切换：2011/2013 为 6 字节 BCD 手机号，2019 为版本号 + 10 字节 BCD 手机号；消息体属性逐位拆解（长度/加密/分包/版本）。下表按消息 ID 排序，可搜索名称或 ID，也可按方向筛选。

二、位置汇报附加项 0x0200

位置信息汇报（0x0200）消息体末尾的附加信息项，按「附加信息 ID + 长度 + 数据」依次排列。含主动安全报警附加项 0x64~0x67（见第六节）。

三、JT/T 809 消息清单 0x1000 ~ 0x9xxx

平台与平台间（下级 ↔ 上级 / 部—省—市—服务商）的数据交换消息：主/从链路登录与连接保持、动态信息交换、平台间转发、监管对象互查、车辆报警上报、查岗、区域线路等。平台间数据交换子业务见第四节。

四、809 平台间数据交换子业务 规范 V2

依据《重点营运车辆联网联控系统动态监控报警信息平台间数据交换技术规范 V2》：适用于服务商企业监控平台与省联网联控系统之间的「两客一危」报警数据交换。以 JT/T 809-2011 为基础，仅调整涉及子业务。统一数据体公共头：VEHICLE_NO(21) + VEHICLE_COLOR(1) + DATA_TYPE(2) + DATA_LENGTH(4)，车牌号按 21 字节 GBK 解析。

督办业务流程

报警数据实时上报后，服务商须对省平台下发的督办请求按时应答；超时未处理由部、省级平台逐级督办。

1
上报报警

企业平台按 0x1200/0x1402 将车辆报警数据实时上传省联网联控系统，并更新报警状态（处理中/已处理/不作处理等）。

2
3 小时未处理 → 省平台督办

报警上报后 3 小时内未处理，省平台向服务商下发 0x9401 督办请求，责令限期（按紧急/一般级别）处理。

0x9401 督办请求
3
12 小时未应答 → 认定未处理

督办请求下发 12 小时内服务商未上报处理结果，省平台认定该报警「未处理」，并纳入考核。

4
部级每日核查督办

部级平台每日 8 时对前一日未处理的报警下发 0x9401 督办，并实时转发至相关省平台。

5
服务商应答

服务商通过 0x1200/0x1412 上报处理结果，或对督办 0x1401 应答，携带处理状态与处理说明。

处理结果 RESULT：0x00 处理中 / 0x01 已处理完 / 0x02 不作处理 / 0x03 将来处理 / 0x04 误报警。

六、主动安全报警附加项 0x64 ~ 0x67

位置汇报（0x0200）扩展的报警附加项：0x64 高级驾驶辅助 ADAS、0x65 驾驶员状态监测 DSM、0x66 胎压监测 TPMS、0x67 盲区监测 BSD。字段结构依据主流公开标准（山东团体标准/苏标体系）。各地私有扩展不同时，无法识别的剩余字节原样展示。
