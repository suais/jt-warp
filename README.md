# JT/T 808 & 809 报文解析工具

在线解析交通部 JT/T 808（2011 / 2013 / 2019）与 JT/T 809 协议报文。
**纯前端实现，无后端、无依赖、无网络请求** —— 报文只在你自己的浏览器里解析，不会上传到任何服务器。

## 使用

直接双击 `index.html` 即可（`file://` 协议下也能正常工作）。
若要作为在线工具部署，把整个目录丢到任意静态托管（GitHub Pages / Vercel / Nginx）即可。

## 功能

### 解析
- 粘贴十六进制报文即时解析，支持空格 / 逗号 / 换行 / `0x` 前缀混排
- 自动剥离 `7E` 首尾定界符，兼容裸报文
- **转义还原**：`7D 02 → 7E`、`7D 01 → 7D`
- **异或校验码**校验，不匹配时给出声明值与计算值对照
- 消息头按版本自动切换：2011/2013 为 6 字节 BCD 手机号，2019 为版本号 + 10 字节 BCD 手机号
- 消息体属性逐位拆解（长度 / 加密 / 分包 / 版本标识）
- 经纬度按位标志判定南北纬、东西经，并给出 1e-6 度转换值
- **报警标志、状态位逐 bit 展开**，命中位高亮并汇总成可读标签
- **位置附加项**按 ID 表逐项解析（里程、油量、胎压、ADAS、DSM、OBD、CAN、GNSS 信噪比等 30+ 种）
- 原始字节视图带分区着色（消息 ID / 属性 / 手机号 / 流水号 / 校验码）与图例
- 容错告警：长度不足、长度偏小、粘包、未收录消息 ID、已加密消息体
- **头部截断不崩页**：消息头不完整时照常展示已解析到的部分与原始字节
- **内嵌报文扫描**：当输入不是一条完整帧（没有 `7E` 定界、首字节不是合法消息头）时，
  自动在字节流里定位符合协议特征的数据段，可一键单独解析。识别两类：
  - **标准消息体块**：28 字节位置块（BCD 时间合法 + 经纬度落在中国境内），并自动连同附加项一起定位结束位置
  - **结构自洽的消息头**：消息 ID 已知且声明的消息体长度恰好落在数据内，同时比对校验码

  典型场景：从平台数据库导出的"报文"字段其实是一条内部定长记录（含自定义包头、
  0x00 填充），真正的 808 消息体藏在其中某个偏移处。

### 构造
填写消息 ID、手机号、流水号、版本、消息体，自动生成合法报文
（自动计算消息体长度、异或校验码、并做转义），支持一键回填解析页。
内置位置汇报 / 终端注册 / 通用应答模板。

### 字典
内置消息 ID（808 与 809）、报警标志位、状态位、位置附加项、终端参数速查表，支持搜索。

## 覆盖的消息

**JT/T 808**（80+ 条）

| 类别 | 消息 |
|---|---|
| 终端管理 | 0x0001 通用应答、0x0002 心跳、0x0003 注销、0x0005 补传分包、0x0100 注册、0x0102 鉴权、0x0107/0x0108 终端属性 |
| 参数与控制 | 0x8103 设置终端参数、0x8104/0x8106 查询参数、0x8105/0x0105 终端控制、0x8108 下发升级包 |
| 位置与报警 | 0x0200 位置汇报、0x0201 位置查询、0x0202 跟踪控制、0x0203 人工确认报警、0x0704 批量位置 |
| 信息交互 | 0x8300 文本下发、0x8301 事件设置、0x8302 提问下发、0x8303/0x8304 信息点播、0x0301 事件报告 |
| 行驶记录 | 0x0700/0x8700 采集命令、0x0702 驾驶员身份、0x0703/0x8701 记录数据、0x0701 电子运单 |
| 多媒体 | 0x0800/0x0801 多媒体上传、0x0802 应答、0x0805 拍摄命令、0x0806/0x0807/0x0808 检索上传、0x8804 录音 |
| 区域路线 | 0x8600~0x8608 圆形/矩形/多边形区域与路线设置、删除、查询 |
| 其他 | 0x0900 透传、0x0901 压缩上报、0x8100 注册应答、0x0705 CAN 总线、0x0706 油量 |
| 苏标扩展 | 0x1210/0x1211/0x1212 报警附件、0x9201 ADAS 附件指令 |

**JT/T 809**（30+ 条）：主/从链路登录、注销、连接保持、动态信息交换、车辆定位信息实时上传与批量上传、
平台间消息转发、监管对象互查、车辆报警上报、平台查岗、区域/线路数据上报。

**809 平台间数据交换子业务**（依据《重点营运车辆联网联控系统动态监控报警信息平台间数据交换技术规范 V2》，
在 0x1200 动态信息交换下按子业务类型细分解析）：
`0x1201` 上传车辆注册信息、`0x120C` 上传驾驶员身份信息、`0x1402` 上报车辆报警信息、
`0x1412` 上报报警处理结果、`0x9401` 报警督办请求、`0x1401` 报警督办应答。
统一公共头为 `VEHICLE_NO(21) + VEHICLE_COLOR(1) + DATA_TYPE(2) + DATA_LENGTH(4)`，
车牌号按 21 字节 GBK 解析。
`0x1402` 的 **报警类型（WARN_TYPE）** 按《规范 V2》附录「报警类型明细」字典解析
（位置相关 0x0001~0x00FF、非位置 0xA001~0xA0FF、视频 0x0101~0x0107、智能监控 0xD201~0xD508 等 100+ 项）。

**主动安全报警**（终端与平台交互，依据山东团体标准/苏标体系）：
`0x0200` 位置汇报新增报警附加项 `0x64` 高级驾驶辅助(ADAS)、`0x65` 驾驶员状态监测(DSM)、
`0x66` 胎压监测(TPMS)、`0x67` 盲区监测(BSD)。其中 `0x64`、`0x65` 按标准字段表细分
（报警 ID / 标志状态 / 报警类型 / 级别 / 前车车速 / 偏离类型 / 疲劳程度 / 车速 / 高程 /
经纬度 / 时间 / 车辆状态 / 报警标识号等），`0x66`、`0x67` 做通用解析。
> 主动安全字段各地标准略有差异，本工具按主流公开标准实现；若与你的平台私有扩展不同，剩余字节会以「扩展数据/未解析剩余字节」原样展示。

## 开发

```bash
# 修改 src/ 后重新打包
node build/bundle.mjs

# 解析器回归测试
node test/regression.mjs

# 页面自检（含 DOM shim 端到端）
node test/pagecheck.mjs
```

`src/parser.js` 是标准 ESM 模块，可直接在 Node 或打包工具中使用：

```js
import { parse, buildFrame, bytesToHex, scanEmbedded, parseRawBody } from './src/parser.js';

const res = parse('7E 02 00 00 2B ... 7E');
console.log(res.msgName, res.protocol, res.checksum.ok);

// 输入不是完整帧时，定位其中内嵌的协议数据
const scan = scanEmbedded('5B 00 00 00 A0 ...');
for (const c of scan.candidates) {
  console.log(c.kind, c.offset, c.length, c.msgName);   // location 64 48 位置信息汇报
}

// 只解析消息体（头部由工具合成）
const r = parseRawBody(0x0200, bytes.slice(64, 112));
```

## 说明与边界

- 字段释义依据交通运输部标准（JT/T 808-2011 / 2013 / 2019、JT/T 809-2011）附录整理。
- **各地监管平台与终端厂商存在大量私有扩展**，同一消息 ID 的消息体结构可能不同
  （尤其 809 车辆定位信息、0x0702 驾驶员身份、0x0704 附加项）。本工具按主流实现解析，
  剩余无法识别的字节会以「未解析的剩余字节」原样列出，便于对照。
- 已加密的消息体（加密方式 ≠ 0）不做解密。
- 报文中若含多个 `7E`（粘包），仅解析第一条并给出提示。
